# Websites domain-shaped queries (sw-foundation-core catalog reference)

Naming note (read before guessing any tool name): the older families suffix their batched variants `-agg` (`get-websites-geography-agg`), while the newer `get-website-analysis-*` referral family spells it out as `-aggregated` (`get-website-analysis-traffic-referrals-aggregated`). Both conventions are live at once. Never derive a name by analogy; resolve it from the live tool list per sw-foundation-core § tool-surface presence.

| Intent | Tool | Key params | Notes |
|--------|------|------------|-------|
| Rank a domain | `get-websites-website-rank` | domain, country | Cheap. Use as a smoke test. Response has `country_rank` + `category_rank` only; NO `global_rank` field. For global rank, pass `country: "ww"` and use the returned `country_rank` (see `website-rank-no-global-field`). `web_source` constraint: `total` only. |
| Traffic + engagement of one domain | `get-websites-traffic-and-engagement` | domain, country, start_date, end_date | Default window: last 90 days. |
| Compare N domains' traffic | `get-websites-traffic-and-engagement` (same tool, looped over each domain) | as above; one call per domain | No batched-over-entities variant exists for this tool. Loop the non-agg tool. |
| Traffic channels (absolute visits, includes Gen AI) | `get-website-analysis-traffic-channels` | domain, country, start_date, end_date, granularity (daily / weekly / monthly), web_source, mtd, main_domain_only. NO `limit` param | Rows are `{date, source_type, visits}`, one row per channel per month, across the live ten-channel taxonomy: Affiliates, Direct, Display Ads, Gen AI, Mail, Organic Search, Organic Social, Paid Search, Paid Social, Referrals. **`Gen AI` carries ABSOLUTE VISITS**, which makes this the cheapest AI-referral signal on the surface (see § AI-referral intent below). 10 credits per month, window-priced; there is no limit lever, so bound the WINDOW. `web_source: mobile_web` is monthly-granularity only. |
| Channel shares plus the referring domains behind them | `get-website-analysis-traffic-channels-share` | domain, country, window, limit | Rows are `{domain, source_type, share}`; `meta.visits` carries the period total and each `share` is a fraction of it. Exactly 2 credits per REQUESTED row (limits 10 / 25 / 50 / 100 charged 20 / 50 / 100 / 200). Its `source_type` vocabulary is FINER than the channels tool's: Search - Organic, Search - Paid, Direct, Affiliates, Display Ads, Social - Paid, Social - Organic, Email, Referrals, Gen AI. Do NOT equate the two vocabularies (`Mail` here is `Email`, `Organic Search` here is `Search - Organic`). Named AI domains live here, under source_type `Gen AI`, alongside `AI Search` (source_type `Search - Organic`), which is an AI-answer surface counted INSIDE organic search and NOT under Gen AI. Their referrer ranks vary by domain and by month, so no `limit` reliably enumerates them; see `## AI-referral intent` below for which tool to reach for. There is NO server-side `source_type` filter; filter client-side after the call. |
| Segment traffic + engagement | `get-segments-traffic-and-engagement` | segment (a Segment ID, NOT a domain), country, window, granularity, metrics, web_source | Desktop and total only; `mobile_web` is rejected. `unique_visitors` is monthly-granularity only. Pair with `get-segments-traffic-sources`, which takes the same Segment ID. Segment IDs come from the account's own segment definitions. |
| Inbound referrers (subdomain-granular) | `get-website-analysis-traffic-referrals-incoming` | domain, country, window, limit | Rows `{share, domain, change}`. Reports subdomains SEPARATELY (tracking.narvar.com and nike.narvar.com come back as distinct rows). `meta` carries free headline extras: total referral `visits`, `total_count` (referring-domain count), `global_ranking`, `category`, `category_ranking`. `get-segments-traffic-sources` takes a Segment ID, not a domain. NO AI-assistant domain appears in this pipeline; for AI referrers see § AI-referral intent below. ~3 credits per row (75 at limit 25); cost shape not yet multi-point grounded. |
| Outgoing referrers (where a domain sends traffic) | `get-website-analysis-traffic-referrals-outgoing` | domain, country, window, limit | Rows `{share, domain, change}`, same `meta` shape as incoming. ~3 credits per row (30 at limit 10); cost shape not yet multi-point grounded. |
| Referral panels including advertisers, publishers, social | `get-website-analysis-traffic-referrals-aggregated` | domain, country, window, limit, referral_type, web_source | Rows `{domain, share, change, visits}`, and note it carries ABSOLUTE visits where the incoming tool does not. ROLLS UP subdomains (narvar.com appears once at 8.68% where the incoming tool splits it into 6.65% plus 2.04%). `referral_type` enum: incoming (default), outgoing, advertisers, publishers, social; the last three REQUIRE `web_source: desktop`. This tool absorbed the advertiser and publisher role of the retired `get-websites-referrals-agg` pipeline; it did NOT absorb that pipeline's AI referrers. ~3.7 credits per row at incoming (96 at limit 25, 374 at limit 100); the advertisers-on-desktop panel priced differently (32 at limit 10). Per `referral-pipelines-divergence`. |
| Similar sites | `get-websites-similar-sites-agg` | domain, limit (NO country param; the live schema does not accept one and a client-side validation rejects it) | Default limit 10. WINDOW CONSTRAINT: explicit start_date/end_date must span EXACTLY 3 months (use start_date 2_months_ago, end_date latest) or the call 400s with "must span exactly 3 month(s)"; omitting both dates is also safe. Response rows carry `affinity` (0..1 similarity); there is NO `similarity_score` field. Per `similar-sites-window-constraint`. |
| Audience overlap | `get-websites-audience-overlap-agg` | domain, domains (comma-joined string, 2-5 domains) | Returns 2^N-1 subset rows in a single batched call. |
| Demographics | `get-websites-demographics-agg` | domain, country | Age + gender breakdown. |
| Demographics OVER TIME | `get-websites-demographics` | domain, country, window, granularity (monthly only), metrics | One row per month, eight share fields. Priced on MONTHS x METRICS with no per-row base (1 month x 2 metrics charged 2; 1 x 8 charged 8; 3 x 2 charged 6), so trimming `metrics` saves proportionally and asking for gender alone costs a quarter of asking for all eight. Unrequested metrics are RETURNED AS NULL, so the response shape never tells you what was requested. Use the `-agg` sibling for a single-period breakdown across domains. |
| Geography | `get-websites-geography-agg` | domain | Per-country breakdown (share + absolute visits per country). Priced on rows AND metrics at once, `rows x (metrics + 1)`: 30 credits at limit 10 with 2 metrics, 70 at limit 10 with the server's default 6. Pass BOTH bounds. Per `geography-agg-cost-shape`. |
| Demographic slice engagement | `get-websites-traffic-by-demographics-agg` | domain, country, age_buckets, gender, metrics | FILTER-then-aggregate (NOT group-by): returns ONE row for the requested age x gender slice, no per-bucket labels. Call once per slice to compare. Use `get-websites-demographics-agg` for the full breakdown. Per `traffic-by-demographics-semantics`. |
| Tech stack | `get-website-content-technologies-agg` | domain, status, limit | ~1 credit/row. Default `status` is installed_and_removed (pass `installed` for the current stack, `removed` for churn). A limited pull is ALPHABETICAL, not ranked: a small limit is an inventory sample, not a top-N. Per `technologies-agg-shape`. |
| Conversion rates | `get-websites-conversion-rates-agg` | domain, vertical | Vertical-specific. Presence varies by account (absent from the grounded connector at both the 2026-06-11 and the 2026-08-06 enumerations, present 2026-05-16, and it did NOT return in the plus-33 expansion); resolve per sw-foundation-core § tool-surface presence. |
| Search (PPC) spend | `get-website-analysis-search-spend` | domain, country, window, currency, data_version, web_source | Rows `{date, currency, ppc_spend}`, one per month; the `ppc_spend` field name survived the rename verbatim. 1 credit per month, window-priced. `data_version`: VERSION_6.0 is current and also supports `web_source: mobile_web`, defaulting to `total`; VERSION_5.0 is deprecated legacy. Max span 39 months, monthly granularity only. `currency` enum: usd (default), eur, gbp, jpy, aud. A single scalar per month; no by-channel breakdown. |
| Ad networks a domain buys or sells through | `get-website-analysis-display-networks-agg` | domain, country, window, limit, ad_network_type, data_version | Rows `{ad_network, share, change}`. `ad_network_type` (incoming default / outgoing) survived the rename, so the one-tool-with-a-direction-parameter model still holds; `change` is populated for incoming only and null for outgoing. `data_version` VERSION_6.0 supports only `web_source: total`. | Social traffic sources | `get-website-analysis-social-traffic-sources-agg` | domain, country, window, limit, traffic_type (all default / organic / paid) | Rows are `{social_network, page, visits_share, visits_change}`, one row per network-plus-PAGE pair, NOT a clean per-network rollup: Facebook recurs with different `page` values, some of which are not social sites at all. | SERP clicks OVER TIME | `get-websites-serp-players` | keyword, country, window, granularity, limit, traffic_source, web_source | Rows `{date, clicks, domain}`. FLAT 1 credit per call across two limits and two window lengths, which makes it one of the cheapest competitive signals on the surface; bound it for PAYLOAD, not for cost. **`limit` caps TOTAL rows across the whole window, not rows per period:** `limit: 5` over three months returned five rows ALL from the FIRST month and nothing from the other two, which reads as missing data rather than truncation. ## AI-referral intent: where to look first

The retired `get-websites-referrals-agg` pipeline was the plugin's AI-referrer proxy. It is GONE, and its AI rows did NOT move into the surviving referral tools: a limit-100 scan of `get-website-analysis-traffic-referrals-aggregated` on nike.com found no chatgpt.com, perplexity.ai, claude.ai, gemini, or copilot row, and `-incoming` at limit 25 shows none either. AI referrers are served by the traffic-channels family now. The ladder:

1. **Direct measurement first, if the account exposes it.** Attempt `get-ai-traffic-landing-pages-agg` (always with an explicit `limit`; it is 1 credit per row) or `get-ai-traffic-overview` (uncharged, but PIN THE WINDOW: the server default spans about three years and rows are months times active LLM sources). CANONICAL ENTITLEMENT NOTE, and the single place this is stated: these tools are PRESENT on the live surface, and whether they return data is an ACCOUNT property, not a server one. On the reference connector they returned 403 "Access forbidden. Upgrade your account." from 2026-06-11 through 2026-08-06, then returned 200 from 2026-08-07 after that account was unlocked. Two observations of one account are not a population, so never state or imply that these doors are gated for everyone. Attempt the call and branch on what comes back: a 200 is direct measurement, a 403 is this account lacking the module.
2. **Default proxy: ONE `get-website-analysis-traffic-channels` call.** Its `Gen AI` row is absolute visits; divide by the summed channel visits for the share of traffic. 10 credits per month, no limit lever. Observed on nike.com 2026-06 worldwide: Gen AI 581,272 visits against a 113,269,470 all-channel total, that is 0.51% of traffic, rising across 2026-04/05/06 (372,850, then 562,111, then 581,272). This is CHEAPER than the retired proxy was, not more expensive.
3. **Named-AI-domain drill-down, opt-in only, and never an enumeration.** `get-website-analysis-traffic-channels-share` at `limit: 50` (100 credits at 2 per requested row). This rung lists the AI sources that reach the top 50 referrers AT THAT LIMIT. It is NOT the set of AI sources sending traffic, and no limit makes it so: measured across two domains and two consecutive months, one Gen AI source crossed the rank-50 boundary between consecutive months and another sat past rank 90, so any fixed floor misses sources on some domain in some month (`ai-traffic-vs-channel-proxy-completeness` carries the ranks). Raising the limit raises the cost linearly and still does not close the gap. A source absent from these rows is UNKNOWN, not zero. When the account exposes rung 1, that is where a named list comes from; this rung is what a gated account can see. Gloss `AI Search` as an organic-search AI-answer surface, never a Gen AI assistant.

Never mix the two source_type vocabularies in one table without a gloss, and never present a channels-derived Gen AI share as direct AI-engine measurement.

## Demand and industry intent

Search-demand and industry-level tools sit beside the per-domain surface. Two carry shape traps worth reading before the first call.

| Intent | Tool | Key params | Notes |
|---|---|---|---|
| Total search volume for a topic | `get-demand-search-trends-aggregated` | country, topic OR keyword_group, window, granularity | Uncharged. Returns ONE row `{volume}` for the WHOLE window with NO `date` field, so despite the name it is not a trend tool: it SUMS the window. Reading a three-month figure as a single month overstates it by roughly the period count. To build a trend, call once per period and assemble client-side. |
| Per-keyword search volume for a topic | `get-demand-search-trends-keywords-aggregated` | country, topic OR keyword_group, window, granularity | Uncharged and LARGE: about 999 distinct keywords and 77 KB on one common topic over two months, past the inline budget. It has NO `limit` parameter, so the bound is a NARROWER TOPIC (plus a shorter window), not a row cap. A broad seed has no safe call. See § payload-budget. |
| Per-domain and per-keyword demand detail | `get-demand-search-trends`, `get-demand-search-trends-keywords` | as above | The non-aggregated siblings; prefer the aggregated forms when only totals are needed. |
| Industry age distribution | `get-industry-demographics-age-distribution`, `get-industry-demographics-age-distribution-agg` | category OR custom_industry (exactly one), country, window, metrics | Monthly granularity only. Same eight-metric enum as the website demographics tools. |
| Industry gender shares | `get-industry-demographics-gender-shares`, `get-industry-demographics-gender-shares-agg` | as above | |
| Industry audience size | `get-industry-unique-users` | category OR custom_industry, country, window | Its `-describe` sibling is uncharged, about 17 KB, and takes no bound parameter. |
| Which industry categories exist | `get-industry-demographics-describe`, `get-industry-unique-users-describe` | none | Near-identical content, about 17 KB each: fetch ONE and reuse it rather than both. |

`custom_industry` takes a GUID from the account's own industry definitions, so it is account-scoped and no default can be shipped.
